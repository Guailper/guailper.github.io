一、MCP 概述

1.1 MCP 是什么

  • MCP 的定义：Model Context Protocol，模型上下文协议
  • MCP 要解决的问题：让 AI 应用以统一方式连接工具、数据和上下文
  • MCP 与传统插件、API 调用、函数调用的区别
  • MCP 的典型应用场景：IDE、知识库、数据库、浏览器、自动化工具

1.2 MCP 的整体架构

  • Host：发起连接并承载 LLM 交互的应用
  • Client：Host 内部负责与 Server 通信的连接器
  • Server：暴露资源、工具、提示词等能力的服务端
  • 三者之间的关系和一次完整调用链路
  • JSON-RPC 2.0 在 MCP 通信中的作用

1.3 MCP 核心原语

  • Tools：让模型执行具体操作
  • Resources：向模型提供上下文数据
  • Prompts：沉淀可复用的提示词模板和工作流
  • Sampling：由 Server 请求模型能力
  • Roots：限制 Server 可访问的工作目录或 URI 范围
  • Elicitation：Server 向用户请求补充信息

1.4 MCP 通信流程

  • 初始化连接：能力协商与协议版本确认
  • 能力发现：tools/list、resources/list、prompts/list
  • 工具调用：tools/call 的请求、参数和返回结果
  • 资源读取：资源 URI、内容类型和上下文注入
  • 错误处理：JSON-RPC 错误码、权限失败、参数校验失败

二、MCP Server 开发入门

  • 选择开发语言和 SDK
  • 定义工具名称、描述和输入参数 schema
  • 实现工具处理函数
  • 暴露资源和提示词
  • 本地启动、调试和日志观察
  • 将 Server 接入支持 MCP 的客户端

2.1 工具设计原则

  • 工具职责要单一，避免一个工具承担过多动作
  • 参数描述要清晰，让模型知道什么时候调用
  • 返回结果要结构化，减少自然语言歧义
  • 对危险操作增加确认、权限或沙箱限制
  • 为失败场景返回可诊断的信息

2.2 安全与权限控制

  • 最小权限原则：只开放必要的文件、接口和操作
  • 用户授权：敏感操作前需要明确确认
  • 数据边界：避免泄露本地文件、密钥和隐私数据
  • 输入校验：防止命令注入、路径穿越和非法参数
  • 审计日志：记录关键工具调用和异常行为

2.3 实战案例

  • 文件系统 MCP Server：读取、搜索、整理本地文件
  • 数据库 MCP Server：查询表结构和执行只读 SQL
  • GitHub MCP Server：读取 issue、PR 和仓库信息

2.4 调试与常见问题

  • 客户端连接不上 Server
  • 工具列表为空或 schema 不正确
  • 模型没有按预期调用工具
  • 工具调用成功但返回内容不可用
  • 权限、路径、环境变量和依赖问题
